# PlannerForge 流程引导

## 参考资料

下面的项目和文章适合用来查接口划分、地图表达、搜索方法、轨迹优化和实时重规划。PlannerForge 保持独立编译，这些链接只作为学习资料。需要移植源码时，先检查对应仓库的许可证和依赖范围。

### RoboMaster 导航案例

- 中国石油大学（华东）RPS 舵轮哨兵导航开源：[论坛文章](https://bbs.robomaster.com/article/1942060?source=4)，[GitHub 仓库](https://github.com/xiix666/sentry26)
- 北京理工大学追梦战队哨兵自主导航：[论坛文章](https://bbs.robomaster.com/article/1940848?source=4)，[GitHub 仓库](https://github.com/Walker152/navi_minco_bit)
- 浙江大学 Hello World 战队 RM2026 轮腿哨兵导航算法开源：[论坛文章](https://bbs.robomaster.com/article/1938205?source=4)，[GitHub 仓库](https://github.com/Polyacetone/HWSentryNav26)
- 青岛大学未来战队 RM2026 导航开源：[论坛文章](https://bbs.robomaster.com/article/1936340?source=4)，[GitHub 仓库](https://github.com/QDU-VRobot/qdu26_sentry_navigation)
- [RoboRTS](https://github.com/RoboMaster/RoboRTS)：RoboMaster 官方开源移动机器人软件栈，可以参考 costmap、全局规划、局部规划和决策模块的组织方式。

### 地图、搜索和轨迹算法

- [Nav2](https://github.com/ros-navigation/navigation2)：重点阅读 `nav2_costmap_2d` 的障碍层与膨胀层，以及 `nav2_smac_planner` 的 2D A*、Hybrid A* 和 State Lattice 实现。
- [Hybrid A* Path Planner](https://github.com/karlkurzer/path_planner)：面向车辆运动学约束的 Hybrid A* 示例，适合研究朝向离散、运动原语、碰撞检查和启发函数。
- [Fast-Planner](https://github.com/HKUST-Aerial-Robotics/Fast-Planner)：包含 kinodynamic search、B-spline 轨迹优化和在线重规划。它面向无人机，搜索状态和优化思路可以用于二维底盘方案设计。
- [GCOPTER](https://github.com/ZJU-FAST-Lab/GCOPTER) 与 [MINCO 论文](https://arxiv.org/abs/2103.00190)：用于理解安全走廊、分段时间、边界状态、轨迹约束和稀疏多项式轨迹表示。
- [EGO-Planner](https://github.com/ZJU-FAST-Lab/ego-planner)：不构建 ESDF 的梯度式局部规划器，可以参考障碍代价、局部轨迹更新和重规划流程。
- [teb_local_planner](https://github.com/rst-tu-dortmund/teb_local_planner)：Timed Elastic Band 移动机器人局部规划器，可以参考时间参数、速度约束、非完整运动学约束和动态障碍处理。
- [Ruckig](https://github.com/pantor/ruckig) 与 [实时轨迹生成论文](https://arxiv.org/abs/2105.04830)：适合研究速度、加速度和 jerk 受限的在线时间参数化。
- [Voxblox](https://github.com/ethz-asl/voxblox)：包含 TSDF 和 ESDF 的增量构建方法。PlannerForge 使用二维地图，距离场的数据组织和更新方法仍可参考。

阅读时先找每个方案的输入、输出和核心数据结构，再看代价函数、约束和更新触发。地图部分对应阶段①，搜索和轨迹生成对应阶段②，局部重规划与动态障碍处理对应阶段④。

当前代码提供一条可以运行的基线链路：

```text
地图图片
  -> simple_map
  -> /grid_map
  -> PathSearch
  -> SamplePath
  -> GenerateTrajectory
  -> OptimizeTrajectory
  -> MINCO 解算
  -> /minco_trajectory
```

地图和轨迹使用 `map` 坐标系，长度单位为 m，时间单位为 s。最终轨迹继续使用 `plan_interfaces/msg/MincoTrajectory`。地图模块与规划器之间的数据格式可以修改，发布端、订阅端和地图查询接口需要一起调整。


## 需要修改和拓展的部分
## ① 地图处理和地图信息传输

当前地图把低于灰度阈值的像素记为障碍，搜索对象是机器人中心点。由于机器人具有实际半径，定位和跟踪也存在误差，需要在地图层加入安全距离处理。

代码入口：

- `src/simple_map/src/simple_map.cpp` 中的 `BuildStaticMap`
- `src/simple_map/src/simple_map.cpp` 中的 `updateDynamicObstacles`
- `src/gcopter/src/global_planning.cpp` 中的 `mapCallBack`
- `src/gcopter/include/gcopter/grid_map_2d.hpp` 中的 `GridMap2D`

处理方式需要覆盖静态障碍和动态障碍，并保持统一的地图原点、分辨率和坐标系。

继续使用 `OccupancyGrid` 时，可以发布处理后的占据栅格。采用距离场或复合地图时，需要定义新的模块间消息，并在 `mapCallBack` 中转换成搜索和碰撞检查可以查询的数据结构。地图信息至少应包含：

- 地图坐标系、原点、分辨率和有效范围
- 静态层、动态层及其更新时间
- 多层地图的合并规则

完成后检查墙边、障碍拐角和狭窄通道。搜索点、连续轨迹采样点和机器人外廓都应位于允许区域内。

## ② 前端搜索、采样和后端优化

`PathSearch::search` 当前使用 Dijkstra。`SamplePath` 直接复制搜索路径，`OptimizeTrajectory` 直接复制初始轨迹，均需要自行填充。需要在这一阶段改善路径长度、转弯质量，同时考虑运动学约束、轨迹平滑性和障碍距离。

代码入口：

- `src/gcopter/src/path_search.cpp` 中的 `PathSearch::search`
- `src/gcopter/src/trajectory_generation.cpp` 中的 `SamplePath`
- `src/gcopter/src/trajectory_generation.cpp` 中的 `GenerateTrajectory`
- `src/gcopter/src/trajectory_generation.cpp` 中的 `OptimizeTrajectory`
- `src/gcopter/src/global_planning.cpp` 中的 `buildContinuousTrajectory`

前端搜索负责生成可达路径。可以尝试 A*、JPS、Hybrid A*、采样搜索或其他方法。代价函数可以使用路径长度、障碍距离、转弯代价和方向变化。输出要保留准确的起点和终点。

采样阶段适合做路径简化、进行基于时间或距离的估计采样和控制点提取等。路径简化后仍需逐段检查障碍。

`GenerateTrajectory` 负责准备边界状态、连接点和每段时间。当前时间由路径长度除以标称速度得到。可以加入速度、加速度、曲率和转向需求，为后端提供初值。

`OptimizeTrajectory` 是后端入口。优化变量、代价函数和约束由实现者选择，输出需要完整填写 `MincoTrajectoryData`。

`buildContinuousTrajectory` 当前使用 MINCO 生成连续轨迹。更换具体解算方法时，在这里接入新的连续轨迹表示，并完成到现有 `MincoTrajectory` 出口格式的转换。

## ③ 25 cm 狗洞处理

这一阶段保留数据结构和接入位置，狗洞识别与轨迹处理方法由实现者完成。轨迹真正通过狗洞时，需要对进入前、洞内和离开后的一段范围写入特殊标志。范围可以按轨迹时间扩展，也可以按路径长度扩展。注意核心在于只让真正穿过洞的轨迹及其前后赋予特殊标志，而不要搞成只要在洞的附近就缩下去。

代码入口：

- `src/gcopter/include/gcopter/traj_representation.hpp` 中的 `CrossHoleInterval`
- `src/gcopter/src/global_planning.cpp` 中的 `updateWaypointSpaciousFlags`
- `src/gcopter/src/global_planning.cpp` 中的 `publishMincoTrajectory`

地图侧需要提供狗洞区域或等价的语义信息。轨迹侧需要求出连续轨迹与该区域的实际相交段，再填写 `enter_time`、`exit_time`、`active_start_time` 和 `active_end_time`。`active_*` 表示加入前后准备范围后的生效区间。

经过狗洞附近、运动方向不符、规划失败和轨迹更新后留下的旧区间都不能生效。一条轨迹多次穿越时，每次穿越使用独立区间。最终由 `publishMincoTrajectory` 写入现有 `cross_hole_*` 数组。

## ④ 动态障碍下的实时更新

`simple_map` 提供三个移动矩形障碍示例，长宽均在 `1 m` 左右，分别沿地图 x 或 y 方向往返运动。规划器收到新地图后检查当前轨迹的剩余部分，发现占据冲突时从当前轨迹位置重新规划。这段代码用于展示动态更新的接口和触发位置。

代码入口：

- `src/simple_map/src/simple_map.cpp` 中的 `updateDynamicObstacles`
- `src/gcopter/src/global_planning.cpp` 中的 `mapCallBack`
- `src/gcopter/src/global_planning.cpp` 中的 `hasTrajectoryCollision`
- `src/gcopter/src/global_planning.cpp` 中的 `FSMCallBack_Timer`

动态障碍数据需要携带时间信息。规划输入应包含障碍位置、速度、预测范围和数据有效期。重新规划需要设置触发间隔和滞回条件，控制地图噪声引起的轨迹切换。

实时更新需要覆盖：

- 动态障碍数据过期或中断
- 当前轨迹即将发生碰撞
- 新轨迹计算超时或失败
- 目标点变化与地图更新同时到达
- 新旧轨迹切换时的位置、速度和时间连续性

规划循环中不加入磁盘读写和阻塞等待。记录搜索、优化、碰撞检查和整次重规划的耗时，再根据更新频率确定计算预算。

## 外部接口

四个阶段开始实现时，先保持以下接口稳定：

```text
/goal_pose              geometry_msgs/msg/PoseStamped
/grid_map               nav_msgs/msg/OccupancyGrid
/Odometry_to_base_link  nav_msgs/msg/Odometry
/minco_trajectory       plan_interfaces/msg/MincoTrajectory
```

地图模块与规划器之间可以改用新的消息。修改 `/grid_map` 时，同步更新 simple_map 发布端、gcopter 订阅端、RViz 显示和第一阶段列出的地图查询代码。最终轨迹出口保留位置、速度、时间和过洞标志信息。
